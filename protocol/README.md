# Protocol specification (draft v0.1)

These documents are **normative**: they define consensus. A rule that two
reasonable implementations could read differently is a specification bug.

Keywords MUST, MUST NOT, SHOULD, and MAY are used as in RFC 2119.

| File | Status |
| --- | --- |
| `encoding.md` | Draft v0.1: integers, varint, hashing, network id |
| `transactions.md` | Draft v0.1: outputs, inputs, txid/wtxid, coinbase, locktime, schemes, signature message, spending rules, weight |
| `blocks.md` | Draft v0.1: header, Merkle root, validation order, chain selection |
| `difficulty.md` | Draft v0.1: aserti3-2d, timestamp rules |
| `subsidy.md` | Draft v0.1: exact integer schedule |
| `genesis.md` | Draft v0.1: construction from Bitcoin headers |
| `addresses.md` | Draft v0.1: Bech32m wallet encoding |
| `pow.md` | Not started: waits for ADR-0003 (RandomX v2 parameter set, key rotation) |
| `p2p.md` | Not started (informative) |
| `params.md` | Not started: canonical constant list hashed into genesis |

Test vectors live in `../test-vectors/` and are regenerated by
`simulations/subsidy.py` and `tools/gen_vectors.py`.
