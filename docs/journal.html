1 November 2026 · Isamu Nagai

Final hardening before the testnet

The last work before the testnet goes live was about making the whole structure tighter without slowing anything down.

The node's wallet is now encrypted. It uses the same format as Strata: a 24-word recovery phrase, Argon2id to protect your passphrase, and AES-256 with an authentication code for the file. The node mines and shows balances from public addresses only. Private keys are decrypted just long enough to sign a payment and wiped right after. On a server you can go further and mine straight to a Strata address, with no keys on the machine at all. The installer now works that way.

The network layer got stricter. Each peer has a budget for how much signature verification it can make a node do, and anything beyond it is dropped unverified. A peer that relays a transaction with an invalid signature is disconnected, because honest nodes check before they relay. A node accepts only a few inbound connections from the same network range, and spreads its own outbound connections across different ranges, chosen at random. That makes it harder for one party to surround a node.

Every parser is now fuzzed continuously. Transactions, blocks, network messages, addresses, recovery phrases, wallet files and the wallet's local web server each get a stream of randomly corrupted input. Anything that parses must re-encode to exactly the same bytes, so no object can have two encodings. It runs on every change and for 45 minutes every night. The first runs, hundreds of millions of inputs, found nothing.

Mining speed is unchanged: none of this touches the miner. The battle tests pass with all of it in place: run 3, with one new check added, passed all 56. What is still ahead before mainnet is on the readiness page. Next: the testnet.

31 October 2026 · Isamu Nagai

Strata wallet and Varvescan explorer

Two new pieces go live with the testnet: a wallet and a block explorer. Together with the node they make up what you need to use Varve, and all three now have a home on the new Download page.

Strata is the Varve desktop wallet, for Windows, macOS and Linux. It runs on your own computer and opens in your browser. Create a wallet and you get a 24-word recovery phrase; your keys are derived from it inside Strata and never leave your machine. The wallet file is encrypted with your passphrase, Strata locks itself when you step away, and every payment is shown in full before it is signed. It takes advantage of a Varve feature from earlier this week: coins that belong to the same address are spent with a single signature, so even a payment that gathers dozens of small coins stays small and cheap. In our end-to-end test, one payment spent thirteen coins with one signature, and it confirmed on the next block.

Varvescan is the block explorer, built into this website. Look up any block, transaction or address: balances, full history, which keys a payment used, and where an address's coins came from. It runs in your browser with no cookies, trackers or third-party code, and it treats everything it receives as untrusted.

Both read from a new public interface in the node, which keeps its indexes exact through chain reorganisations and restarts; the multi-node tests now check that on every change.

There is also a mainnet readiness page. It lists what is proven, what is designed, and what still has to happen before mainnet, and items only move to done with evidence you can check.

Next: the first public seed node goes online and the first testnet release is published, and you will be able to download all of this and start mining.

31 October 2026 · Isamu Nagai

A working node, and a testnet born from today's Bitcoin blocks

Varve now runs. The reference node, miner and wallet are written in Rust, with no third-party Rust packages at all. The only external code is the two pinned cryptographic libraries the protocol depends on: liboqs for the post-quantum signatures, and RandomX for mining. It passes every consensus test vector, which makes it the third implementation that agrees on the rules.

What it can already do, tested with separate nodes talking over the network on every change:

  • mine blocks with RandomX on an ordinary CPU;
  • sync from other nodes, header-first;
  • send a payment signed with ML-DSA that relays, confirms and shows up in the other wallet;
  • recover from a chain split by switching to the chain with more work, without losing payments;
  • restart from disk exactly where it left off.

An AI-assisted review of the node code found no deviation from the specification and fifteen robustness issues, including two ways a node could get stuck. All are fixed or documented, with regression tests.

The testnet now has a genesis block too. It is anchored to Bitcoin blocks 973,970 to 973,975, mined earlier today, and every node verifies those six headers against Bitcoin's real proof of work each time it starts. It is a rehearsal of exactly how mainnet will launch.

The whitepaper is updated to draft 0.3. Next step: bring the first public seed node online, so anyone can download the node and start mining testnet coins. Testnet coins have no value. Their job is to let as many people as possible try to break Varve before mainnet.

31 October 2026 · Isamu Nagai

The first independent review, and what it changed

An independent reviewer, who asked to stay anonymous, went through the protocol this week. A second, public review with a name attached will follow. I asked for the review to be adversarial, and it was. It found one critical issue and several high-severity ones, and I'm grateful for every one of them.

The critical one: an anti-spam rule in the sync logic could, in an edge case, keep a node on a chain with less work than a competing one. That breaks the most basic rule of proof of work. It is fixed, and the specification now states plainly that a node must always validate any chain with more work than its own.

Other fixes from the review:

  • Real post-quantum signatures and real RandomX hashing are now tested on every change, on both x86_64 and ARM64. They were previously skipped in automated tests.
  • The genesis procedure is now fully implemented and tested against real Bitcoin headers, including every possible one-byte tampering.
  • A much larger test-vector suite, plus a second implementation of the rules written only from the specification. It agrees with the prototype on every vector.
  • An emergency-migration idea that was only a sketch is no longer claimed as a feature. Varve promises only what is specified and tested.

Every finding and its resolution is public in audits/. This is how I want Varve built: find the problems early, fix them in the open, and never claim more than the code can back up.

31 October 2026 · Isamu Nagai

The first battle test: two real bugs found, both fixed

Today we turned on Varve. Not in public yet, but on a private test network where the only job was to break it.

We built a battle-test harness that starts real nodes and attacks them. It sends blocks that create coins out of thin air, spend the same coin twice, or steal coins with someone else's signature. It sends blocks with impossible timestamps or fake difficulty, and longer secret chains that try to undo a payment that already confirmed. It sends thousands of randomly corrupted blocks, transactions and network messages. Every attack block carries real RandomX proof of work and every signature is a real post-quantum signature, so the node can't reject anything for a cheap reason. A separate implementation of the rules checks the same inputs, and the two must agree on every single one. Then we pulled the plug on running nodes and damaged their data files.

The first run passed 53 of 55 tests. The two failures were real:

  • A damaged spot in a node's own block file made it distrust a good block forever. The node treated its broken local copy as proof the block was invalid. It then refused the clean copy from other nodes and cut those nodes off. On a live network, one bad disk sector could have isolated a node. Now the node recognises a damaged local copy, throws it away and fetches the block again.
  • A transaction's witness data could be re-encoded by anyone relaying it. Since this week, Varve can cover several coins from the same key with a single signature. A relayer could swap a full signature for that short shared form. That changed the transaction's size and witness ID, though never what it pays or to whom. The rule is now strict: where the shared form applies, it is the only valid form, so every transaction has exactly one valid encoding.

The second run passed all 55. The two charts, with the date and version tested, are on the security page. The harness and raw results are in the repository, so anyone can rerun them.

The same work brought two improvements of its own. The difficulty schedule now starts two hours after genesis, which removes a burst of too-easy blocks right at launch. Spending many coins from one address now needs only one signature: in the battle test, one transaction spent 398 coins and weighed about 21 KB, where separate signatures would have taken over 2 MB. A full block of 131 separately signed transactions verifies in under 0.1 seconds on a modest two-core machine.

What this does not prove: no test suite proves there are no bugs. Network-flood testing and an independent human code audit are still ahead, and both must happen before mainnet. The public testnet is where everyone else gets to try.

30 October 2026 · Isamu Nagai

Why I'm building Varve

Bitcoin is the most important monetary experiment of our lifetime. It proved that money can be scarce, open and owned by no one. But every coin in it is protected by elliptic-curve signatures, and a large enough quantum computer would break them. Nobody knows when that day comes. It might be decades away; it might never come. What I do know is that money meant to be held for generations should not depend on one cryptographic assumption lasting forever.

So I asked a simple question: if you designed neutral digital money today, for a 50 to 100 year horizon, what would it look like? Varve is my answer.

  • Post-quantum from the first block. Every coin is protected by ML-DSA or SLH-DSA, the signature standards NIST finalized in 2024. There will never be legacy coins to rescue.
  • Cryptography that can evolve. Every output records which scheme protects it, so new schemes can be added and weak ones retired by a planned upgrade instead of a crisis.
  • A launch nobody can game. The genesis block is derived from six future Bitcoin blocks. Not even I can start mining early. No premine, no allocation, no presale. Ever.
  • Small enough to verify. Capacity is set by what an ordinary laptop can check.

Everything is being built in the open: the specification, every design decision, the simulations and the code. I would rather be proven wrong in public now than after launch. If you see a flaw, open an issue. That is the most valuable thing anyone can do for Varve right now.
